## Why these batches exist

The Batch 7 tree was probed read-only against the regenerated seed-17 histories (`fc_probes.py`, directive author, 20 Oct 2026). Three facts about the accepted numbers were established and are the premises of this extension:

- **P-A.** A paid use is one of two acts. `energy_audit.blocks` yields a hop block for every arrival along `route.{i}.path.{n}` (n ≥ 1) and one content block per route for `route.{i}.element`. In `pair-seed-17`, 87 of 137 uses are hops. Bob's 12 weak-seat uses are all hops; he completes no content block at seat 5 or 6. The conditioning index therefore counts transit through a weak seat and work at a weak seat as the same event.
- **P-B.** Every route passes through a vital-ring support seat by construction (`cognitive_routes.route`: seats 5/7 for accumulation, 6/8 for expenditure). The same program produces identical content blocks for the IEE and the EIE (50 each) but 87 versus 148 hops. The relation-sensitive quantity in these histories is the hop traffic and the seat prices, not provenance.
- **P-C.** `source_seat` is `position_of(supplier_tim, element)`: a type-table lookup. Coverage 4/12 is satisfied without the supplier having completed any paid use at the supplied element (Alice-IEE: 0 Ne uses, 1 Fi hop). Received uses do not interleave with self uses; every history ends inside the collective, so a return to self-sourced use at a conditioned seat is unobservable at this workload.

Batch 8 makes each of these a measured column. Batch 9 produces the one history in which P-C's missing observation can occur, on a program that demands all eight elements rather than the two U11 asks for.

### 8.2 `conditioning_v2/classes.py`

### 8.3 Measures added to `measures.summarize` (all additive)

Every measure below is computed under **both** provenance readings where it depends on `source`, and once where it does not.

1. **Conditioning by class.** `conditioning_content = (received weak content uses, all weak content uses)` and `conditioning_hop = (received weak hop uses, all weak hop uses)`, per actor, with ID lists. The existing `conditioning` column is unchanged and stays first.
2. **Hold by class.** `hold_content`, `hold_hop`, same shape as `hold`.
3. **Self-retention (`kept_self`).** For each received use, `kept_self` is True iff a later paid use by the same actor at the same seat and element exists whose `source` is `"self"` or `"world"` under the same reading. Report `internalisation = (received uses with kept_self, received uses)` per actor and per weak seat. On every Batch 7 history this is expected to be `0/n`; record it as a finding, not a failure.
4. **Observed supply.** A received weak use u is *observed-supplied* by s ∈ `source(u)` iff s completed at least one **content** block at `element(u)` at a transaction index strictly less than u's. `observed_coverage` uses the existing coverage denominator and counts only observed-supplied uses; the existing coverage column is relabelled **structural coverage** in headers only (no cell changes). Report the supplier map twice: structural (existing) and observed.
5. **DCNH margin.** For every DCNH observation already produced (all-use, received-and-kept wide, received-and-kept narrow), add `margin = max(loads) − second_max(loads)` (0 when the greatest cell is tied; `N/A` when every load is 0). Add two further observations with the same shape, **content-only** and **hop-only** (source-independent). Greatest-load cells are rendered as before, followed by `(margin m)`. No threshold is applied and no cell is suppressed; the margin is reported, not interpreted.
6. **Price of type.** Per actor per history: `uses`, `hops`, `content`, `time_total`, `time_hop`, `time_content`, `energy_total` (CT Table 13 block energy), and the same four counts split by ring (`mental`/`vital`) and by seat (1–8). Also `support_traffic`: the count of hops whose arrival seat equals the route's `support_seat`, by seat.

## Batch 9 — The eight-element solo phase (`pair-solo8` composition)

**Purpose:** one composition in which (a) a received use at a weak seat can be followed by a self- or world-sourced use at the same seat, so `internalisation` (8.3.3) can be nonzero, and (b) every actor's eight seats are demanded, so DCNH loads, conditioning by class and price of type are observed on the full field rather than on the two elements U11 asks for. This is the only history in the project in which conditioning, as distinct from membership, is observable, and the only one in which a subtype reading is not simply the workshop's Si/Te demand refracted through type.

**Premises established by probe on the pinned engine (20 Oct 2026):**
- **P-D.** `WorkflowRequest.elements` overrides a recipe's elements within the same Fold family (`workflow_records.py:79` admits any list whose first letters match the recipe's). `Express/expenditure` with `elements=('ne','ti')` succeeds for an IEE and routes to seats 1 and 4; the recipe default lands on 7 and 6. The recipe table covers Ni, Fi, Te, Si in both faces, so with the attitude flip all eight elements are reachable.
- **P-E.** The U11 workshop (the `setup11` seeding) constructed over `hle_unified.workflow_execution.WorkflowEngine` instead of `CollectiveEngine` runs `group/step/proposed/instantiate/finish` to `succeeded`. One world can therefore hold a collective phase and a direct-request phase. An engine cannot be constructed over a world that already has paid work, so the composition must start on `WorkflowEngine`.
- **P-F (open).** A direct `WorkflowRequest` in the workshop world was refused with `paid addressed native workflow uptake required`; the request needs the uptake records that `tests_c7_workflow.fixtures.cell(…, prepare_only=True)` prepares, and that fixture seeds its own equipment (`DEVICE`, `LOAN`). This is the batch's R9 risk and is resolved in step 9.1.1 before anything else.
