# Glossary

| Term | Definition and computation |
| --- | --- |
| Actor / TIM | An actor is a committed identity with a committed type profile (TIM), recovered by the engine audit and checked in [audit.py](conditioning_v2/audit.py), `uses`. |
| Paid use | One newly completed native hop or seat-content block, counted using the engine's canonical block and completed-use logic in [audit.py](conditioning_v2/audit.py), `uses` (I5). |
| Seat | The Model A position of the used element for the actor's TIM, from kernel `position_of`, checked by [audit.py](conditioning_v2/audit.py), `_validate_record` (I1). |
| Dim | Kernel `fields(seat)["dimensionality"]`, with weak ≤ 2 and strong ≥ 3, checked by [audit.py](conditioning_v2/audit.py), `_validate_record` (I1). |
| Source: self / world / tuple | Selected exact input revisions resolve to self if any producer is the consumer and none is another actor, world if no actor producer remains, or a sorted tuple of other committed actors taking precedence, in [audit.py](conditioning_v2/audit.py), `_operation_source` (I2). |
| Wide / narrow | Wide selects source.N, source_input and input.N while narrow selects only source.N/source_input; both deduplicate exact revisions and attribute the operation's resulting source to every paid block in [audit.py](conditioning_v2/audit.py), `_semantic_sources` and `uses`. |
| Source seat / relation | Each supplier's element seat and kernel directional relation to the receiver align with its tuple position and satisfy the landing-position check in [audit.py](conditioning_v2/audit.py), `_validate_record` (I3). |
| Kept | A later paid use by the same actor at the same seat and element marks an earlier use kept, with True preserved under history growth in [retention.py](conditioning_v2/retention.py), `uses` (I4). |
| Received | A use is received exactly when its source is a non-empty other-actor tuple under the named reading, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Conditioning index | Received weak-seat uses divided by all weak-seat uses per actor, with a zero denominator reported N/A, in [measures.py](conditioning_v2/measures.py), `summarize` and [tables.py](conditioning_v2/tables.py), `ratio`. |
| Hold index | Kept received uses divided by all received uses across all receiver seats, with an empty denominator N/A, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Use profile | Counts and occurrence IDs grouped by actor, seat, source class and kept, where other denotes any source tuple, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Supplier map | Each weak receiver seat lists suppliers and their use IDs, counting a multi-supplier use once per supplier, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Coverage | Distinct weak actor/seat pairs receiving at least one use from a supplier holding that element at a strong seat, divided by all committed actors' weak seats, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Episode coverage | Coverage accumulated through each explicit episode index with a fixed population denominator, using scheduler events for population histories and declared harness events for U11, in [measures.py](conditioning_v2/measures.py), `locate_uses` and `summarize`. |
| Supplier HHI / concentration | Sum of squared supplier incidences divided by the square of all supplier incidences, counting multi-supplier uses once per listed supplier, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Ordered pair / forward / reverse | A supplier-to-receiver direction with its forward and reverse received-use IDs is assembled after counting uses in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Sterile pair | A pair is sterile under the named reading only when it has zero received uses in either direction in that history, in [measures.py](conditioning_v2/measures.py), `summarize`. |
| Benefit-family uses | Supplier/receiver incidences with the kernel's benefit or inverse-benefit transformation are grouped independently of display names in [measures.py](conditioning_v2/measures.py), `summarize`. |
| DCNH two ways | The same Phase 7 axis loads, tilts, cell associations, formula sums and greatest-load cells are computed on all uses and on received-and-kept uses in [measures.py](conditioning_v2/measures.py), `dcnh` and `history`. |
| All-use vs received-and-kept | All-use includes every paid use regardless of source, while received-and-kept selects tuple-sourced repeated uses for each reading in [measures.py](conditioning_v2/measures.py), `summarize`; all-use must equal the engine observation (I5). |
| Loads / tilts / axis cells / formula sums | Loads and tilts follow kernel axes (1,3), (2,4), (5,7), (6,8), associated cells depend on TIM, and formula sums follow D,C,N,H order in [measures.py](conditioning_v2/measures.py), `dcnh`. |
| Greatest-load cells / comparison | All maximal-load cells are retained, and agree/diverge compares the full all-use and received-kept observations rather than labels alone in [measures.py](conditioning_v2/measures.py), `dcnh` and [tables.py](conditioning_v2/tables.py), `_render_reading`. |
| Inactive actor | A committed actor with zero completed paid uses still appears in coverage denominators and table rows in [measures.py](conditioning_v2/measures.py), `summarize`. |
| World material | An exact revision committed with no actor, or an operation with no selected actor-produced input, yields world and contributes to all-use counts and weak-use denominators but not received counts, in [audit.py](conditioning_v2/audit.py), `_operation_source`. |
| Delivery event | A completed paid use consuming selected exact revisions committed by another actor is evidenced by the producer transaction join in [histories_delivery.py](generate/histories_delivery.py), `first_delivery`, under the named reading. |
| Use ID / transaction / operation revision / block end | A history-local uN identifies a canonical paid-block occurrence and its exact journal location in [measures.py](conditioning_v2/measures.py), `locate_uses`, with zero-based transaction indices and native completion boundaries. |
| N/A | A zero denominator or unavailable experiment is explicitly undefined rather than measured zero, rendered in [tables.py](conditioning_v2/tables.py), `ratio` and [reports.py](conditioning_v2/reports.py). |
| Pair / pair-sterile / triad | These name the requested fixture compositions, with pair-sterile recording a prediction rather than an observed outcome and the IEE/SLI/LIE triad unavailable, in [histories_delivery.py](generate/histories_delivery.py), `composition_status`. |
| Resource model | legacy-r4 and grade-v1 are existing engine resource models selected by [histories.py](generate/histories.py), `build`, while all delivery histories retain legacy-r4; these are separate from provenance readings. |
| Seed | A seed selects population task counts/order or, for delivery histories, only the nonbinding initial budget, in [histories.py](generate/histories.py), `build`, and [histories_delivery.py](generate/histories_delivery.py), `build`. |
| Checkpoint SHA-256 | The digest identifies the exact native serialized world/checkpoint bytes and is checked after restoration by [tables.py](conditioning_v2/tables.py), `load_histories`, rather than serving as a substitute for available generated data. |
| Kind: hop / content | A paid use is a hop (arrival along a route path) or a content block (the route's seat-content work); recovered from committed route attributes in [classes.py](conditioning_v2/classes.py), `classify`. |
| Conditioning / hold by class | The Batch 7 conditioning and hold indices restricted to one kind of use, in [classes.py](conditioning_v2/classes.py), `summarize`. |
| Kept self | A received use later followed by a self- or world-sourced paid use by the same actor at the same seat and element, monotone under history growth, in [classes.py](conditioning_v2/classes.py), `kept_self`. |
| Internalisation | Received uses with kept self divided by received uses, per actor and per weak seat; N/A when nothing is received, in [classes.py](conditioning_v2/classes.py), `summarize`. |
| Observed supply / observed coverage | A received weak use whose supplier completed a content block at that element earlier in the history; coverage over the same denominator as structural coverage, in [classes.py](conditioning_v2/classes.py), `summarize`. |
| Structural coverage | The Batch 4 coverage column, relabelled: the supplier holds the element at a strong seat by TIM, regardless of work done. |
| Margin | Greatest axis load minus the runner-up on a DCNH observation; 0 when tied, N/A when every load is zero, in [classes.py](conditioning_v2/classes.py), `margin`. |
| DCNH five ways | All uses; received and kept (wide, narrow); content-only; hop-only, each with its margin, in [classes.py](conditioning_v2/classes.py), `summarize` and `render`. |
| Price of type | Per actor and per seat: uses, hops, content, time and CT Table 13 block energy, by ring and seat, in [classes.py](conditioning_v2/classes.py), `summarize`. |
| Support traffic | Hops whose arrival seat is the route's own vital-ring support seat, per seat, in [classes.py](conditioning_v2/classes.py), `summarize`. |
| pair-solo8 / phase marks | The Batch 9 composition: uptake probe, the pair sequence, then Alice's eight-element program on one `WorkflowEngine` journal; the manifest's phase marks are the transaction indices ending each phase, read by [solo8.py](conditioning_v2/solo8.py), `sequences`. |
| Source-class sequence | Per (actor, seat, element), the class of each use in order (S self, W world, O other; lower-case not kept), per phase, in [solo8.py](conditioning_v2/solo8.py), `sequences`. |
| Field three ways | An actor's eight-seat uses, hops, content, time and energy over the probe+collective phase, the solo phase, and the whole history, with DCNH greatest cells and margins, in [solo8.py](conditioning_v2/solo8.py), `field_three_ways`. |
| Element override | `WorkflowRequest.elements` replacing a recipe's elements within the same Fold family (first letters equal), the mechanism that reaches the other attitude's seats; witnessed in `tests/test_09_solo8.py`. |
